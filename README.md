# mk网-Claude Code 从入门到实战 一课玩转顶级Agent

获课：itazs.fun/21545/mk网-Claude Code 从入门到实战 一课玩转顶级Agent

很多人对 Claude Code 的认知还停留在“终端里能聊代码的机器人”，这低估了它。Claude Code 的本质是一个具备完整工具链的编码代理：它能读你的整个仓库、编辑文件、跑测试、执行 git 命令，并在动手前征求你的同意。本文用一节课的篇幅，带你走通从安装到进阶的完整闭环。

第一步：安装与登录，两分钟的事。 最省事的路径是下载 Claude Desktop，登录付费账号后直接打开“Code”选项卡，无需额外安装。如果你偏好终端，用 npm install -g @anthropic-ai/claude-code 即可（Node 18+），切勿加 sudo，否则后续文件权限会出问题。装完后进入项目目录，运行 claude，输入 /login 完成浏览器授权。

第二步：理解唯一必须记住的安全规则。 Claude 在修改文件或运行命令前永远会先问你。你会看到一个 diff 和三个选项：批准单次更改、本次会话自动批准编辑、或者拒绝并说明理由。任何时候按 Shift+Tab 可以切换模式：默认模式最安全，Plan 模式先出方案不动手，适合重构前审查范围；Accept Edits 模式则适合信任场景下的批量操作。记住：只要没提交，git checkout 永远是你的后悔药。

第三步：用五个提示完成第一次实战。 进入项目后，依次尝试：让它用五条要点总结代码库结构和入口；问它“用户认证在哪里处理”；让它给某个函数加两行 docstring 并审查 diff；粘贴一个失败测试的报错让它定位修复；最后让它暂存更改并写一条符合你仓库风格的 commit message。这五步覆盖了探索、定位、编辑、调试、版本控制五个核心能力。

第四步：一个被低估的高价值动作。 每个项目第一次使用时，运行 /init。这会在项目根目录生成 CLAUDE.md，记录你的代码约定和项目上下文。Claude 每次会话开始时会自动读取它，后续回答会天然贴合你的项目规范。Claude Code 创建者 Boris Cherny 的团队就是这么做的：只要发现 Claude 哪里做错了，就把规矩写进共享的 CLAUDE.md，确保它下次不再犯同样的错误。

实战心法：把注意力放在流程上，而非逐个修 bug。 新手常犯的错误是 AI 改错一处就手动纠正一处。正确的做法是：发现 AI 在某类问题上反复出错时，去修它的“规则手册”，而不是修那一行代码。进阶阶段值得关注两个能力：Checkpoints 会在每次更改前自动保存代码状态，按两次 Esc 或输入 /rewind 即可回退；Subagents 可以把独立任务（比如“跑测试”或“验证改动”）交给隔离的上下文去执行，主对话不被中间过程淹没。

从安装到第一个 commit，再到把规则沉淀为可复用的工程资产，这一课走完，你手里就不再是一个“会写代码的聊天框”，而是一个真正能替你跑腿、试错、收尾的顶级 Agent。
